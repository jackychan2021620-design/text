# 0.3.1 使用反馈修复记录

用户报告：粘贴小红书链接后整个窗口显示未响应；输入旧 DeepSeek Key 没有明确反馈；首页新增首个项目后没有继续新增入口。

## 改动与验证

1. 主进程不再导入或初始化 Chromium。网页只在本程序启动的独立子进程中运行，传回有限的笔记和图片清单；主进程验证来源及本次临时目录后后台保存。子进程不打开经营数据库、不读取 AI Key。
2. 独立进程有启动和心跳超时，取消会关闭本次启动的进程树；不会结束其他浏览器。导入提示和设置窗口非模态，等待期间仍可操作工作台。
3. 首页始终显示新增及管理产品入口，完整点击回归连续新增三个产品。
4. 旧 DeepSeek Key 使用相同官方接口和原凭据条目。保存后自动获取实际模型；连接计时、取消、401和超时有明确反馈。设置窗口可立即收起，小尺寸下保存按钮可见。
5. Windows 使用原生 Credential Manager 后端；保存失败仍保留当前运行 Key 并说明重启需重输，不写入明文配置。

本地自动测试共65项通过，包含：故意挂起子进程时主界面定时器继续、打开设置与保存产品；超时取消；模拟 Windows 创建进程本身迟迟不返回时主界面仍响应；模拟慢图片保存时主界面仍响应；旧 Key 原样发送到官方接口并自动保存服务返回模型；认证错误可见；设置慢请求关闭；临时目录之外图片拒绝。

安装包构建会在 Windows 再执行全部测试，并运行打包后及安装后的挂起子进程隔离检查和浏览器离线提取检查。以绑定提交的成功构建记录为准，不能用本地测试代替 Windows 结果。
